Functions in Shell Scripts:
---------------------------
A Function is a reusable block of code.
Instead of writing the same commands multiple times, we place them inside a function and call the function whenever needed.
A function is a named block of commands that can be executed whenever required.

 > Why do we use Functions?
---------------------------
Functions help us:
 . Reduce duplicate code
 . Make scripts easier to read
 . Make scripts easier to maintain
 . Reuse the same logic multiple times
 . Divide a large script into smaller sections

functions and loops can make something happen multiple times, but they solve completely different problems.
A simple way to remember it is:
 . Function = Reuse code
 . Loop = Repeat execution
Those are not the same thing.

 > First Understand the Problem Each One Solves
Problem 1 - I don't want to write the same code again and again.
Solution?
Functions

Problem 2 - I want to execute something many times.
Solution?
Loops

Real Example

Suppose your company wants a Daily Server Health Report.

Every report should display

Current Date
Current User
Hostname
Memory Usage
Disk Usage

#!/bin/bash

whoami

whoami
hostname

Look carefully.
How many times did we write
Three times.

If tomorrow the manager says:
"Please also display CPU usage."

Now you must modify

Server 1
↓
Server 2
↓
Server 3

You may even forget one place.

Using Function:
---------------
#!/bin/bash
health_report() {
date
whoami
hostname
free -h
df -h
}

echo "===== Server 1 ====="
health_report

echo

echo "===== Server 2 ====="
health_report

echo

echo "===== Server 3 ====="
health_report

Now the report exists only once.
If tomorrow the manager says
"Add CPU usage."
You only modify

health_report() {
date
whoami
hostname
free -h
df -h
lscpu
}

Done.
Every place automatically gets updated.
This is the biggest advantage of functions.

 >>> Now Where Does Loop Come?
Suppose instead of three servers,
you have 100 servers.

Without loop

health_report
health_report
health_report
...
100 times

Not practical.
Now use a loop.

for server in Server1 Server2 Server3
do
    echo "===== $server ====="
    health_report
done

Here, the loop is not replacing the function
The loop is repeatedly calling the function, They work together.

Hands-on:
---------
Function + Loop together (Very common)

#!/bin/bash

echo "Date"
date

free -h
}

for server in Dev QA Production
do

echo "=========="

done

Here,
 . Function defines what a health report is.
 . Loop decides how many times to generate it.

1. Create a file (vi sample.sh), add the above script
2. Provide the executable permission (chmod +x sample.sh)

A function defines a task once. A loop decides how many times that task should run.

Reusable means: Write once and use many times.

 > Now Let's Introduce Loop
Suppose instead of
 . Development
 . Testing
 . Production

your company has 100 servers

Are you going to write

...
100 Times

No, now use a loop.

Now the function executes three times automatically.

Very Important
 . The loop is not replacing the function.
 . The loop is repeatedly calling the function.

 > Think of Them as Two Different Jobs
1. The function answers
What work should be done?
2. The loop answers
How many times should that work be done?

| Question 					| Answer |
|----------					|--------|
| **What work should be done?** 		| **Function** |
| **How many times should the work be done?** 	| **Loop** |
| **Why use a function?** 			| To avoid duplicate code and make changes in one place. |
| **Why use a loop?** 				| To avoid manually repeating the same execution. |

Passing Arguments to Scripts:
-----------------------------
Until now, every value was either
hardcoded
or
entered by the user.
There is another method.
We can send values while executing the script.

What are Arguments?
Arguments are values passed to the script during execution.

Positional Parameters:
| Parameter | Meaning             |
| --------- | ------------------- |
| `$0`      | Script name         |
| `$1`      | First argument      |
| `$2`      | Second argument     |
| `$3`      | Third argument      |
| `$#`      | Number of arguments |
| `$@`      | All arguments       |

Hands-on:
---------
1. Create a file (vi student.sh), 

#!/bin/bash
echo $1
echo $2

provide permission to the file (chmod +x student.sh)
2. now execute this with the values (./student.sh Akshiv DevOps)
3. Here 
Akshiv
DevOps
are called Arguments.

Understanding:
Rahul
↓
$1
DevOps
↓
$2

Example Using Labels:
---------------------
#!/bin/bash

now, edit the file (vi student.sh) - paste the same, execute and check for the output.

we need to give

to know the Number of Arguments:

Exit Status and Return Codes:
-----------------------------
This is one of the most important Bash concepts in DevOps.

What is Exit Status?
Every Linux command returns a number after execution.
That number tells us whether the command succeeded or failed.

This number is called the
Exit Status
or
Return Code

Success
Exit Code = 0
Means
Command executed successfully.

Failure
Exit Code ≠ 0
Means
Something went wrong.

Flow:
-----
Run Command
↓
Linux Executes
↓
Returns Exit Code
↓
0
Success
↓
Non-Zero
Failure

Example:
--------
mkdir demo

Check
echo $?

Output
0
Meaning
Success.

Now execute...
cd unknown

Output
No such file or directory

Now check
echo $?
Output
1
or another non-zero value, depending on the command.

Meaning
Failure.

What is $?
$?
contains the exit status of the last executed command.

Example
pwd
echo $?
Output
0

Real-Time Example:
------------------
ping -c 1 google.com
If successful
echo $?
Output
0

Using Exit Status in if:
#!/bin/bash

mkdir project

if [ $? -eq 0 ]
then
    echo "Folder Created Successfully"
else
   echo "Folder Creation Failed"
fi

This is commonly used in automation scripts.
