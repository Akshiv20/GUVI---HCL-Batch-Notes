RedShift = Unstructured Database
This is considered to be a Data warehouse, which means it acts like (godown) where we can store multiple Databases.
By using Database we can be able to execute multiple queries, same like RDS and we can report this to our other teams according to the necessary situations.

Redshift is considered to be Amazon product, but in market we do have a lot of other products like HADOOP, Informatica etc.,

The purpose of this unstructured database is to connect with structured and semi-structured and collect data's from them

The simple difference between database and database warehouse is, 
DB = this used to run the business
DB warehouse = this used to analyse the business

Where exactly we are using Redshift? At what purpose?
	we are using Redshift mainly for analyzing purpose, In real-time, there will be a lot of data's getting stored all over the places, it is not manually easy to analyze that, hence we are writing some kind of algorithms through there we are collecting our data's into database and this redshift works accordingly.

Advantages:
Only using Redshift, we can build multi query operations, in normal databases we can run only single query at a time.
This will automatically compress the data by using encoded schema's

The best example: https://www.covid19india.org/ (currently not active)
In this website, we can see the entire data from all over the district, this data will be collected and stored separately and together setted up in a warehouse, and all these data outputs will be shown by using the analytics tools like Redshift, Hadoop or others.

How RedShift works?
Client Application (Top-tier) - where our analytical and data-mining reports will be running -- this will get connected to the leader node (this node will be created automatically) via JDBC and ODBC (JDBC = JAVA Database Connector; ODBC = Other Database Connector) -- the main work of leader node is to collect data's from the various databases and this will run the queries inside the separate compute nodes (this one acts like slave for the leader) [why it is running all the queries separately? Because, if everything going to run inside the same node, this may takes a lot of times, hence by separating the tasks the job will done easily and faster] -- inside compute node we got something called (node slices) this means even the queries will split once again inside the compute node parallelly run the queries column-wise for more faster option -- once the queries done the leader node will collect the data and send it to the CLient Application as an output.
The main job of Leader Node is not running the queries this will collect the data's and re-route it to the separate compute node for the job done.
This setup will be called as Cluster. Even we can maintain multiple-clusters also according to the quatity of the data available.

We are going to run 2 different types of queries
1. Amazon in-built one = Query editor
2. SQL Workbench = 3rd party tool [only for the 3rd party tool, we need JDBC and ODBC; but for in-built we don't require this one, because it is automatically connected]

when we are setting up the Redshift cluster, we need to chose which type of nodes we need to set-up, wee got 2 different types of storage
1. Dense Storage (RA) - When there are huge number of content and the processing time can be little bit slow, then we can use this one, mostly for huge amount of data, this is the recommended one. {ex: Millions & Billions of Data's}
2. Dense Compute (DC2) - Data's are not really huge but I need the processing that needs to be more faster then we are going to use this one. {Thousands' or Lakhs'}
We are going to choose this under the following criteria:
1. Data Quantity
2. Complexity of Queries
3. Downstream Systems.

In other words, we will call this tools as ETL (extract, transform & load)
