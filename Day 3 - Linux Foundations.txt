Module 1 - Linux File System Hierarchy

What is a File System?
A File System is simply the way an Operating System stores and organizes data.

Imagine your laptop as a huge office building.
Inside that building,
 . Every department has its own room.
 . Every room stores specific files.
 . Everything has a fixed place.
Linux follows exactly the same idea.

Instead of random folders, Linux organizes everything inside one root directory.

Windows vs Linux:
-----------------
| Windows        | Linux                                 |
| -------------- | ------------------------------------- |
| C:\            | /                                     |
| D:\            | No separate drives shown like Windows |
| Backslash \    | Forward Slash /                       |
| Multiple roots | Single Root                           |

Windows
C:\Users\John\Documents

Linux
/home/akshiv/Documents

Notice there is only one starting point.
That starting point is called
/
called Root Directory
Everything exists under it.

Root Directory:
---------------
Draw this on the board.

               /
      _________|_________
     |    |    |    |    |
   bin  home  etc  var  usr
 
Everything begins here.
Linux does not ask Which drive?
Instead it asks Which folder under Root?

Module 2 - File Types in Linux:
-------------------------------
What is a File?
"What is a file?"
PDF
Word Document
Image
Video

In Linux, that's only one type of file.

Linux treats almost everything as a file:
 . Documents
 . Folders
 . Hard disks
 . USB drives
 . Printers
 . Keyboard
 . Mouse

This design gives Linux a consistent way to interact with hardware and software.

What is the purpose of the file command?:
-----------------------------------------
Windows mostly relies on file extensions.
Example:
resume.pdf

Windows says:
This is a PDF because it ends with .pdf.

Linux works differently.
It looks at the actual contents (also called the file signature or magic number), not just the filename.

For example:
touch test.txt

Now check it:
file test.txt

Output:
test.txt: empty

Notice it doesn't say:
Text File
because the file is empty.

Now add some content.
echo "Hello Linux" > test.txt

Run:
file test.txt

Output:
ASCII text
Linux examined the contents.

Another Example
Create this:
touch movie.mp4

Now check:
file movie.mp4

Output:
empty

Even though the extension is .mp4, Linux knows it is not actually a video.

Now rename it:
mv test.txt image.jpg

Run
file image.jpg

Output
ASCII text
Even though the name ends with .jpg, Linux still recognizes it as a text file.

Types of Files in Linux:
------------------------
| Symbol | File Type         | Description                          |
| ------ | ----------------- | ------------------------------------ |
| `-`    | Regular File      | Documents, images, scripts, binaries |
| `d`    | Directory         | Contains files and folders           |
| `l`    | Symbolic Link     | Shortcut to another file             |
| `c`    | Character Device  | Keyboard, terminal, serial devices   |
| `b`    | Block Device      | Hard disks, SSDs, USB storage        |
| `p`    | Named Pipe (FIFO) | Inter-process communication          |
| `s`    | Socket            | Communication between processes      |

Regular File (-):
-----------------
Stores user data.

Examples:
 . notes.txt
 . photo.jpg
 . script.sh
 . data.csv

Directory (d):
--------------
A directory organizes files.

Example:
 . Documents/
 . Downloads/
 . Projects/

Symbolic Link (l):
------------------
Acts like a shortcut.
Similar to a Windows shortcut.

Character Device (c):
---------------------
Transfers data one character at a time.

Examples:
 . Keyboard
 . Mouse
 . Terminal

Linux example:
/dev/tty

Block Device (b):
-----------------
Transfers data in blocks.

Examples:
 . HDD
 . SSD
 . USB Drive

Linux example:
/dev/sda

Pipe (p):
---------
Used for communication between processes.

Explain:
Imagine two programs talking to each other.

Socket (s):
-----------
Used by applications for communication.

Examples:
 . Database server
 . Web server

Module 3 - Hard Link vs Soft Link:
----------------------------------
Original document:
Project.docx

You want another way to access it.
There are two methods.

Hard Link:
----------
Creates another name pointing to the same data on disk.

Project.docx
↓
Same storage location
↑
Project_Backup

Both names point to the same inode (data).
Delete one?
The other still works.
Delete the original?
The hard link still works because the data still exists until all hard links are removed.

Soft Link (Symbolic Link):
--------------------------
Creates a shortcut.

Shortcut
↓
Original File

Delete the original?
The shortcut becomes broken.
Exactly like deleting the target of a Windows shortcut.

Hard Link vs Soft Link Comparison:
----------------------------------
| Hard Link                              | Soft Link                              |
| -------------------------------------- | -------------------------------------- |
| Shares the same inode                  | Has its own inode and points to a path |
| Survives deletion of original filename | Breaks if target is deleted            |
| Cannot link directories (normally)     | Can link directories                   |
| Usually cannot cross file systems      | Can cross file systems                 |

Hands-on – Soft Link:
---------------------
Create a file:
echo "Linux Training" > notes.txt

Create a symbolic link:
ln -s notes.txt shortcut.txt

View the links:
ls -l

Example:
lrwxrwxrwx shortcut.txt -> notes.txt

Notice:
l
means symbolic link.

Open it:
cat shortcut.txt

Output:
Linux Training

Delete the original:
rm notes.txt

Now:
cat shortcut.txt

Output:
No such file or directory

Explain:
The shortcut still exists, but the target file is gone.
[make sure to delete the file, (rm -rf shortcut.txt)

Hands-on – Hard Link:
---------------------
Create a new file:
echo "DevOps" > original.txt

Create a hard link:
ln original.txt hardlink.txt

View inode numbers:
ls -li

Example:
123456 original.txt
123456 hardlink.txt
Notice that both files have the same inode number, meaning they refer to the same underlying data.

Delete the original filename:
rm original.txt

Read the hard link:
cat hardlink.txt

Output:
DevOps

Explain:
The data still exists because another filename (hard link) still points to it.
[make sure to delete the file, (rm -rf hardlink.txt)

Module 4 - User and Group Management:
-------------------------------------
Why Do We Need Users?
Can everyone use the same account on a company server?
The answer is no.

Reasons:
 . Security
 . Accountability
 . Different access levels
 . Easier management

Example:
| User    | Role                   |
| ------- | ---------------------- |
| alice   | Developer              |
| bob     | Tester                 |
| charlie | DevOps Engineer        |
| diana   | Database Administrator |

Each user has separate files, passwords, and permissions.

What is a Group?
A group is a collection of users who need similar access.

Example:
Developers
├── Alice
├── Bob
└── John

Instead of assigning permissions to each person individually, you assign permissions to the group.

Types of Users:
---------------
| User Type   | Purpose                                     |
| ----------- | ------------------------------------------- |
| Root        | Full control of the system                  |
| Normal User | Daily work                                  |
| System User | Runs services like web servers or databases |

Explain:
 . Root can do anything.
 . Normal users have limited privileges.
 . System users are created for services and usually don't log in interactively.

Useful Commands:
----------------
| Command  | Purpose                                                   |
| -------- | --------------------------------------------------------- |
| `whoami` | Display the current logged-in user                        |
| `id`     | Show user ID (UID), group ID (GID), and group memberships |
| `groups` | List the groups the current user belongs to               |
| `who`    | Show users currently logged into the system               |

Hands-on – Explore User Information:
------------------------------------
Run:
whoami

Show detailed identity:
id

Example:
 . uid=1000(student)
 . gid=1000(student)
 . groups=1000(student),27(sudo)

Explain:
 . uid → User ID
 . gid → Primary Group ID
 . groups → All groups the user belongs to

List group memberships:
groups

Show logged-in users:
who

Important Note:
---------------
Creating, deleting, or modifying users requires administrator (root) privileges.

sudo adduser trainee
sudo passwd trainee
sudo groupadd developers
sudo usermod -aG developers trainee

Module 5 - Password Management:
-------------------------------
 . Every user has a password.
 . Passwords are stored securely (not in plain text).
 . Only administrators can reset another user's password.
 . Linux authenticates users before granting access.
Passwords ensure that only the authorized user can log in and access their resources.

Where Does Linux Store Passwords?
/etc/passwd

This was true many years ago, but modern Linux systems store encrypted password hashes in:
/etc/shadow

| File          | Purpose                                                               |
| ------------- | --------------------------------------------------------------------- |
| `/etc/passwd` | User account information (username, UID, home directory, login shell) |
| `/etc/shadow` | Encrypted password hashes and password aging information              |

Explore /etc/passwd:
--------------------
Display a few entries:
cat /etc/passwd

Example:
student:x:1000:1000:Student:/home/student:/bin/bash

Explain each field:
| Field           | Meaning                             |
| --------------- | ----------------------------------- |
| `student`       | Username                            |
| `x`             | Password is stored in `/etc/shadow` |
| `1000`          | User ID (UID)                       |
| `1000`          | Group ID (GID)                      |
| `Student`       | Description (GECOS field)           |
| `/home/student` | Home directory                      |
| `/bin/bash`     | Default login shell                 |

Explore /etc/shadow:
--------------------
Attempt:
sudo cat /etc/shadow

Example:
student:$6$abcxyz...:19800:0:99999:7:::

Explain:
 . You cannot read passwords.
 . The long string is a password hash, not the original password.
 . Linux compares hashes during login.

Changing Passwords:
-------------------
Change Your Own Password
passwd

Linux asks:
 . Current password
 . New password
 . Confirm new password

Change Another User's Password (Administrator)
	sudo passwd trainee
Only administrators can do this.

Lock a User Account
	sudo passwd -l trainee
This prevents the user from logging in.

Unlock the Account
	sudo passwd -u trainee

Delete the User
----------------:
Basic command:
sudo userdel trainee

This removes:
 . User account
 . Entry from /etc/passwd
 . Entry from /etc/shadow
 . Group membership information

However, it does NOT remove the user's home directory.

Check:
ls /home

You may still see:
student
trainee
The account is gone, but the files remain.

Delete the User and Home Directory:
-----------------------------------
Usually, when an employee permanently leaves, you also remove their home directory.
sudo userdel -r trainee

The -r option removes:
 . User account
 . Home directory (/home/trainee)
 . Mail spool (if present)

Now verify:
ls /home

Output:
student

Verify the User is Deleted:
---------------------------
Check:
id trainee

Output:
id: 'trainee': no such user
Or:
grep trainee /etc/passwd
No output means the account no longer exists.

Important Note:
---------------
You cannot delete a user who is currently logged in.

Example:
sudo userdel trainee

Possible error:
userdel: user trainee is currently used by process 1234

First check:
who
or
ps -u trainee
Then log out that user or terminate their processes before deleting the account.

Deleting a Group
First, list groups:
cat /etc/group
Or:
cut -d: -f1 /etc/group

Suppose the group is:
developers

Delete it:
sudo groupdel developers

Verify the Group
Run:
grep developers /etc/group
No output means the group has been removed.

Can We Delete a Group if Users Still Belong to It?:
---------------------------------------------------
Sometimes No.

If the group is a user's primary group, Linux will refuse.
Example:
sudo groupdel developers

Error:
groupdel: cannot remove the primary group of user 'trainee'

Why?
Every user must have one primary group.

You must either:
 . Delete the user first, or
 . Change the user's primary group.

Example:
sudo usermod -g users trainee

Now delete the group:
sudo groupdel developers

--------
| Command                               | Purpose                                |
| ------------------------------------- | -------------------------------------- |
| `sudo adduser trainee`                | Create a new user                      |

Module 7 - Linux Permissions:
-----------------------------
Why Do Permissions Exist?
Imagine a company.

Developer:
Can edit source code.

Tester:
Can only execute the application.

Customer:
Can only use the application.

Not everyone should have the same access.
Linux permissions enforce this.

Three Permission Categories
Every file has permissions for:
| Category   | Meaning                     |
| ---------- | --------------------------- |
| User (u)   | Owner of the file           |
| Group (g)  | Members of the file's group |
| Others (o) | Everyone else               |

Three Permission Types:
| Symbol | Meaning |
| ------ | ------- |
| `r`    | Read    |
| `w`    | Write   |
| `x`    | Execute |

What Does Each Permission Mean?
-------------------------------
Read (r)
For a file:
 . View its contents.

For a directory:
 . List the names of files inside.

Write (w)
For a file:
 . Modify the file.

For a directory:
 . Create, rename, or delete files within it (provided execute permission is also present).

Execute (x)
For a file:
 . Run it as a program or script.

For a directory:
 . Enter (traverse) the directory with cd and access items inside (subject to permissions).

Understanding ls -l:
--------------------
Run:
ls -l

Example:
-rwxr-xr--

| Section | Meaning            |
| ------- | ------------------ |
| `-`     | Regular file       |
| `rwx`   | Owner permissions  |
| `r-x`   | Group permissions  |
| `r--`   | Others permissions |

Permission Breakdown
rwx
│││
││└── Execute
│└── Write
└── Read

Numeric Permissions:
Each permission has a numeric value.
| Permission | Value |
| ---------- | ----- |
| Read       | 4     |
| Write      | 2     |
| Execute    | 1     |

Examples
Read + Write + Execute
4 + 2 + 1 = 7

Result:
rwx
Read + Execute
4 + 1 = 5

Result:
r-x
Read Only
4

Result:
r--
No Permission
0

Result:
---

Common Permission Values:
-------------------------
| Number | Permission |
| ------ | ---------- |
| 777    | rwxrwxrwx  |
| 755    | rwxr-xr-x  |
| 744    | rwxr--r--  |
| 700    | rwx------  |
| 644    | rw-r--r--  |
| 600    | rw-------  |

Symbolic Permissions:
---------------------
Instead of numbers, Linux also allows symbolic notation.
| Symbol | Meaning      |
| ------ | ------------ |
| `u`    | User (owner) |
| `g`    | Group        |
| `o`    | Others       |
| `a`    | All users    |

Operations:
| Symbol | Meaning                 |
| ------ | ----------------------- |
| `+`    | Add permission          |
| `-`    | Remove permission       |
| `=`    | Set permissions exactly |

Examples:
chmod u+x script.sh
Add execute permission for the owner.

chmod g-w notes.txt
Remove write permission from the group.

chmod o+r report.txt
Add read permission for others.

chmod a+x install.sh
Give execute permission to everyone.
