Day 12 - Programming & Scripting 
================================
Yesterday we learned how to write a shell script. Today we'll learn how to make Linux run that script automatically, detect problems, record everything that happened, and automate daily system administration tasks.

Module 1: Scheduling Tasks with Cron
What is Cron?
Imagine you have an employee who never sleeps.

You tell him:
 . Every day at 9 AM clean the office.
 . Every Sunday create a backup.
 . Every month generate a report.
He never forgets.

Linux has the same employee.
That employee is called Cron.
Cron automatically runs commands or shell scripts at a specified time.

Instead of manually executing:
./backup.sh
Linux itself executes it.

Real-Time Example:
------------------
Suppose you are a Linux Administrator.
Every night at 11 PM
You must
 . Backup important files
 . Compress logs
 . Delete temporary files
Nobody wants to wake up daily at 11 PM.

So you tell Linux:
"Run this script every day at 11 PM."

Linux remembers forever.
That is Cron.

Terminologies:
--------------
Cron: 
Background service that checks schedules.

Think:
"Scheduler"

Cron Job:
A scheduled task.

Example:
Run backup.sh every day
That is one Cron Job.

Crontab:
Cron Table.
A file containing all scheduled jobs.

Think:
Time
Command

Example
0 23 * * * /home/user/backup.sh

Cron Daemon:
Daemon means background service.
Cron daemon continuously checks

Is it time?
Yes?
Run the script.

Cron Time Format:
Cron has 5 timing fields
* * * * * command

Looks confusing.

Let's simplify.
 . Minute
 . Hour
 . Day
 . Month
 . Weekday

Example
30 8 * * * script.sh

Means
8:30 AM every day

Understanding Each Field:
-------------------------
Minute
0-59
Example
15
Means
15th minute

Hour
0-23
Example
14
Means
2 PM

Day
1-31
Example
10
Means
10th day of month

Month
1-12
Example
7
Means
July

Weekday:
--------
0-7
0 or 7 = Sunday
1 = Monday
2 = Tuesday
...
6 = Saturday

Special Characters
*
Means
Every
Example
* * * * *
Every minute.

,
Means
Multiple values
Example
1,15,30
Run on
1st
15th
30th minute

-
Means range
Example
1-5
Means
Monday to Friday

/
Means interval
Example
*/10
Every 10 minutes.


Common Cron Examples
--------------------
Every minute
* * * * *

Every hour
0 * * * *

Every day at midnight
0 0 * * *

Every Sunday
0 8 * * 0
8 AM Sunday.

Every Monday-Friday
0 9 * * 1-5
9 AM.

Viewing Existing Cron Jobs:
Command: crontab -l
Shows,
Current Scheduled tasks.

Creating Cron Jobs:
Commands: crontab -e
Opens editor,
Example 
0 18 * * * /home/ubuntu/backup.sh
save & Done.

Removing Cron Jobs:
Command: crontab -r
Deletes all cron jobs.
Use carefully.

Module 2: Script Debugging Techniques:
--------------------------------------
What is Debugging?
Debugging means
Finding and fixing mistakes inside a script.
Programmers rarely write perfect code on the first attempt.
They debug.

Real-Time Example:
------------------
You wrote
Backup completed.
But no backup file exists.
Something went wrong.
Now you investigate.
That investigation is debugging.

Types of Errors:
----------------
1. Syntax Error
Wrong script structure.

Example

if [ $a -gt 5 ]
echo "Hi"
fi

Missing
then

Script fails immediately.

2. Runtime Error
Script starts correctly.
Fails while running.

Example
cp file.txt backup/

But
file.txt

doesn't exist.

3. Logical Error
Script runs.
No error.
But wrong result.

Example
Instead of adding
10+5

You accidentally subtract.
Script finishes.
Wrong output.

Useful Debugging Commands:
--------------------------
bash -x
Shows every command being executed.

Example
bash -x test.sh

Output
+ pwd
+ ls
+ cp
Very useful.

set -x
Inside script
set -x
Linux prints every executed line.

set +x
Stops debugging.

echo
Most common debugging tool.

Example
echo "Current username is $USER"
Shows variable value.

Hands-on:
---------
1. Create a file (vi test.sh), paste the below content

#!/bin/bash

a=10
b=20

echo "Before calculation"

sum=$((a+b))

echo "Answer=$sum"

2. Run, 
bash -x test.sh
Observe execution line by line.

Real-time Examples 1:
---------------------
Backup Script Fails
Imagine every night a backup runs.

Script:

Morning comes.

The administrator sees

Instead of guessing, run

Immediately you know:
The file

Without -x, you might spend 30 minutes checking the wrong things.

Example 3 – Cron Job Isn't Working

Suppose Cron runs

With bash -x:

Module 3: Error Handling Basics:
--------------------------------
What is Error Handling?
Error handling means
Detecting whether a command succeeded or failed.

Instead of assuming everything works,
the script checks.

Real-Time Example:
------------------
Suppose your backup fails.
Without checking,
script still says
Backup Successful
This is dangerous.
Good scripts verify everything.

Exit Status
Every Linux command returns a number.
0
Means
Success.

Anything other than 0
Means
Failure.

Checking Exit Status
echo $?

Example

mkdir test
echo $?

Output
0
Success.

Wrong command
mkdir test
again
echo $?

Output
1
Failure.

Hands-on:
---------
1. Create a file (vi sample.sh), paste the below content

#!/bin/bash

mkdir backup

if [ $? -eq 0 ]
then
    echo "Created"
else
    echo "Already exists"
fi

2. provide permission for file (chmod +x sample.sh)
3. execute the file (./sample.sh) 
1st time output: Created
execute it for the 2nd time, 
2nd time output: mkdir: cannot create directory ‘backup’: File exists
Already exists

Module 4: Logging Script Output:
--------------------------------
Logging means Saving script output into a file.
Instead of displaying only on screen,
store it permanently.

Real-Time Example:
------------------
A company backup runs at midnight.
Nobody watches the terminal.
Next morning, administrator opens
backup.log

to check
 . Started?
 . Completed?
 . Failed?
 . Time taken?
That is logging.

Why Logging?
Troubleshooting
Audit
History
Error tracking
Performance monitoring

Redirection:
------------
Overwrite log
>

Append log
>>

Example:
echo "Backup Started" >> backup.log

Logging Errors:
2>
Stores errors only.

Logging Entire Script:
./backup.sh > backup.log 2>&1

Hands-on: (1) [Simple Logging]
---------
1. Create a file (vi log.sh)
2. Paste the below script

#!/bin/bash
echo "Backup Started"
date
hostname
echo "Backup Completed"

3. Provide permission (chmod +x log.sh)
4. now, run the script (./log.sh > backup.log)
5. Open the file now (cat backup.log)

Hands-on: (2) [Appending Logs]
---------
1. Create another file (vi sample.sh)
2. Paste the below script

#!/bin/bash
echo "===================="
echo "Backup Started"
date
echo "Backup Completed"

3. Provide permissions (chmod +x sample.sh)
4. now, run the script (./sample.sh >> backups.log)
5. Run it 3 more times
6. Open the file now (cat backups.log)

Hands-on: (3) [Capturing Errors]
---------
1. Create another file (vi logfile.sh)
2. Paste the below script

#!/bin/bash
echo "Checking Files"
ls Documents
ls xyz
echo "Script Finished"

3. Provide permissions (chmod +x logfile.sh)
4. now, run the script (./logfile.sh > backup1.log 2>&1)
5. Open the file now (cat backup1.log)

Explanation:
------------
now we can see no (2) denotes stderr [standard error]
> = redirects
&1 = move this to (1) denotes stdout [standard output]

So What Does 2>&1 Actually Mean?
Take File Descriptor 2
(stderr)
and redirect it
to wherever
File Descriptor 1
(stdout)
is currently pointing.

| Number | Name   | Used For                 |
| ------ | ------ | ------------------------ |
| **0**  | stdin  | Keyboard or input source |
| **1**  | stdout | Normal output            |
| **2**  | stderr | Error output             |

Real-Time Example:
------------------
A DevOps Engineer deploys a website.
Deployment takes 20 minutes.

Without logging:
----------------
Deployment Failed

That's all you know.

With logging:
-------------
Downloading Source Code...
Installing Packages...
Building Application...
Docker Image Created...
Deployment Completed

If it fails:
------------
Downloading Source Code...
Installing Packages...

Error:
Internet Connection Lost

The administrator immediately knows where the problem occurred.
