Data Flow using OSI Model:
--------------------------
OSI stands for
Open Systems Interconnection, it is simply a model that explains how one computer communicates with another computer over a network.
It is not a Software, Hardware, not installed anywhere; This is only a reference model. Engineers use it to understand how data moves.
OSI Layers
7 Application
6 Presentation
5 Session
4 Transport
3 Network
2 Data Link
1 Physical

 > Practical Data Flow
----------------------
Browser
↓
HTTP
↓
TCP
↓
IP
↓
MAC Address
↓
Ethernet/Wifi
↓
Cable

Layer 7 - Application:
Where users interact
Example: Chrome, Firefox, Edge
Protocols: HTTP, HTTPS, FTP, SMTP

Protocols used:
Different applications use different protocols.
Some common ones are:
| Protocol | Purpose                   |
| -------- | ------------------------- |
| HTTP     | Load websites             |
| HTTPS    | Secure websites           |
| FTP      | Transfer files            |
| SMTP     | Send emails               |
| POP3     | Receive emails            |
| IMAP     | Synchronize emails        |
| DNS      | Resolve domain names      |
| SSH      | Secure remote login       |
| Telnet   | Remote login (not secure) |

Protocols are simply rules.
Example:
HTTP defines
 . how browsers ask for pages
 . how servers reply
 . what headers are used
 . what status codes mean

Layer 6 - Presentation:
This layer prepares the data before sending it.
Its main jobs are:
 . Data format = Different systems store data differently.
ex: an image may be JPEG but another application may require PNG (This layer helps ensure data is in a usable format)
 . Encryption = (password: Hello123), Without encryption, someone can read it, with encryption this becomes unreadable; so only the intended receiver can decrypt it.
 . Compression = 100 MB compressed to 25 MB, less data travels over the network (Ex: ZIP, GZIP)
Example:
HTTPS encrypts data before transmission.

Layer 5 - Session:
Responsible for:
 . Establishing communication
 . Maintaining Sessions
 . Closing Sessions
Example: Keeping your login session active on a website.

Layer 4 - Transport:
Responsible for:
 . Reliable communication
 . Packet sequencing
 . Error checking
Protocols: 
 . TCP (Transmission Control Protocol) = Reliable
How it works:
 > Establishes a connection.
 > Sends data.
 > Receiver acknowledges receipt (ACK).
 > If a segment is lost, it is sent again.
 > Data is reassembled in the correct order.
used for: Banking, Login, Email, Web browsing

 . UDP (User Datagram Protocol) = Fast but not reliable
UDP does not establish a connection.
It simply sends data.
If a packet is lost, it is not retransmitted.
used for: Video streaming, Gaming, Voice calls.

Layer 3 - Network
Responsible for routing using IP addresses.
Examples:
192.168.1.10
10.0.0.5
172.31.10.20
Routers operate here.
Responsibilities
 . Assign logical addressing (IP).
 . Route packets between networks.
 . Choose the best available path.

Layer 2 - Data Link
Once the packet reaches the local network, the Data Link Layer is responsible for delivering it to the correct device on that network.
Users MAC addresses.
Example MAC:
00:1A:2B:3C:4D:5E
Switches operate here.

Layer 1 - Physical
Responsible for transmitting raw bits.
Examples:
 . Ethernet cable
 . Fiber optic cable
 . Wi-Fi radio signals.

----------------------------------------
When you open:

the journey looks like this:

Layer 7 (Application)

↓
Layer 6 (Presentation)
The request is encrypted using TLS.
↓
Layer 5 (Session)
A secure communication session is established.
↓
Layer 4 (Transport)
TCP splits the request into segments, numbers them, and ensures reliable delivery.
↓
Layer 3 (Network)
IP addressing determines where the request should go across the internet.
↓

Frames are created and sent to the next device using MAC addresses.
↓

The frames are transmitted as electrical, optical, or radio signals.

What Does the Lock 🔒 Symbol Mean?
When you see this in the browser:
🔒 https://amazon.com

it means:
 . The connection is encrypted using TLS.
 . The server has presented a valid certificate.
 . The browser successfully verified that certificate.
It does not mean the website is trustworthy in every sense—it only means the connection is secure and the website proved control of its identity.

What is SSL?
SSL stands for Secure Sockets Layer
It was the original technology used to encrypt communication between a client and a server.
Today, SSL is considered obsolete because it has known security weaknesses.
Modern systems no longer use SSL for secure communication.

What is TLS?
TLS stands for Transport Layer Security
TLS is the modern and secure replacement for SSL.

When people say:
SSL Certificate
they are usually referring to a certificate that is actually used with TLS.
The term "SSL certificate" has remained popular even though modern websites use TLS.

What is an SSL/TLS Certificate?
A certificate is a digital identity card for a website.

What Information Does a Certificate Contain?

A certificate contains information such as:
 . Domain name (e.g., www.amazon.com)
 . Organization or owner (depending on certificate type)
 . Public key (used during encryption)
 . Certificate validity period (start and expiry dates)
 . Name of the Certificate Authority (CA) that issued it)
 . Digital signature from the CA
This information allows the browser to verify the website's identity.

Capstone Hands-on Lab:
----------------------
Objective
Investigate how a browser request reaches a web server and verify connectivity using Linux networking tools.

Tasks
1. Display your machine's IP address using ip addr or hostname -I.
2. Identify the default gateway with ip route.
3. Verify internet connectivity using ping 8.8.8.8.
4. Resolve the IP address of github.com using nslookup or dig.
5. Use traceroute github.com to observe the packet path.
6. Check whether port 443 on github.com is reachable using nc -zv github.com 443.

7. Send an HTTPS request using:
curl -I https://github.com
Identify the HTTP status code and important response headers.

8. List listening services on your system using:
ss -tuln

9. Identify services running on ports 22, 80, or 443 if present.
If two Linux VMs are available, connect from one to the other using SSH and execute:
 . hostname
 . whoami
 . pwd
 . uptime
